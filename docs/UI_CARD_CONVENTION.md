# UI 卡片式开发约定（Card-First Convention）

> **状态**：生效（2026-08，Issue #70）
> **范围**：全项目 UI（Authenticator / Developer / Settings 及所有从其进入的子页面、对话框、底部表单）
> **强制级别**：项目级 UI 约束。新增/修改 UI 必须遵守，评审时作为必查项。

## 1. 为什么卡片式

卡片式容器把"一条数据 / 一个分组 / 一个条目"封装为视觉上独立、圆角、带表面色的块，
达到以下目标：

- **层次清晰**：Provider → Account → TOTP → Recovery 的逻辑路径在视觉上有明确的分级容器；
- **分组语义**：同属一个条目的字段（名称、码、计数、操作）天然聚合，不散落；
- **一致性**：整个 app 无论进入哪个页面，都用同一套卡片语言，学习成本低；
- **可维护**：全局统一 token / 组件，未来改视觉是一次性改动。

## 2. 强制规则

以下情形**必须**使用卡片容器（而不是裸平铺的 Row / 无背景的列表行）：

| 场景 | 示例 | 必须使用 |
|------|------|----------|
| 列表行 / 条目 | Provider 行、Account 卡、TOTP 卡、Recovery set 卡、Developer entry 卡 | ✅ |
| 分组内容块 | 账户卡内的 TOTP 行、恢复码卡内的码行 | ✅（外层为卡） |
| 表单分区 | Add TOTP 字段、Add/Edit Recovery 字段 | ✅（字段用卡片分组） |
| 弹窗 / 底部表单的说明区 | Migration preview、扫描提示 | ✅ |

**例外**（允许不使用卡片，因为系统组件本身已是标准容器）：

- `ModalBottomSheet` 本身（但内部字段/列表仍按上表卡片化）；
- `AlertDialog` 本身（但内部分组内容仍按上表卡片化）；
- 全屏相机取景框（QrScannerScreen 的相机 Preview）。

## 3. 使用方式

### 3.1 首选：复用统一卡片组件

- `com.rescueauth.v2.ui.components.RescueAuthCard` —— 竖向内容卡片（默认中性 surface 填充、`CardTokens.shape` 圆角、统一内边距）。
- `com.rescueauth.v2.ui.components.RescueAuthRowCard` —— 单行（Row 布局）卡片，content 是 `RowScope`，可直接用 `Modifier.weight(...)`。默认中性 surface 填充。

```kotlin
RescueAuthCard {                       // 标准竖向卡
    Text("Account")
    TotpInlineRow(...)
}

RescueAuthRowCard(onClick = { ... }) { // 可点击单行卡
    Text("GitHub", modifier = Modifier.weight(1f))
    Icon(...)
}
```

### 3.2 或：使用全局 token

如需原生 `Card` / `ElevatedCard`，必须引用统一 token，禁止硬编码颜色/圆角/内边距：

```kotlin
import com.rescueauth.v2.ui.theme.CardTokens

Card(
    shape = CardTokens.shape,
    colors = CardDefaults.cardColors(containerColor = CardTokens.containerColor()),
) { /* ... */ }
```

### 3.3 全局 token 单一来源

`com.rescueauth.v2.ui.theme.CardTokens`（`app/.../ui/theme/Dimens.kt`）定义了：

| token | 含义 |
|-------|------|
| `containerColor()` | 标准卡片填充（`surfaceContainer`） |
| `elevatedContainerColor()` | 强调/可点击卡填充（`surfaceContainerLow`） |
| `shape` | 卡片圆角（`CornerRadius.md`） |
| `contentPadding` | 卡片内边距（`Spacing.md`） |
| `listSpacing` | 卡片间间距（`Spacing.sm`） |
| `listOuterPadding` | 卡片列表距容器边距（`Spacing.md`） |

## 4. 评审检查项（Code Review 必查）

- [ ] 列表行 / 条目是否用了 `RescueAuthCard` / `RescueAuthRowCard`，或引用 `CardTokens`？
- [ ] 是否存在硬编码 `surfaceContainer*`、`RoundedCornerShape(...)`、`Spacing.md` 替代 token 的写法？
- [ ] 新增子页面是否延续卡片式（而非裸平铺）？
- [ ] 卡片内容是否为纯 UI 模型（不含 Room 实体 / secret 明文）？

## 5. Studio 视觉设计（2026-09-13）

本节替代 2026-09-07 的 Flat UI 样式约定。产品范围、Card-First 分组边界、认证与存储契约保持原样。

- 暖白画布与主题 surface，分类与控件沿用现有主题强调色；2026-09-26 品牌图形改为已选定的 E2 蓝金窄柄钥匙。
- 首次开启页：居中蓝金钥匙与品牌名 → 一行本机加密说明 → 底部单一开启操作；认证方式留在主按钮内，旧版导入仍为独立入口。移除重复品牌栏、深色画面底板、“你的保险库。”与功能标签；小屏或大字体时可滚动到两项操作。
- 账户：一张概览、搜索入口、服务目录；不重复堆放多组统计。添加按钮明确区分验证码与新建服务。首页标题与 Dock 标签统一使用“账户 / Accounts”；内部 Authenticator 路由、领域模型与产品能力定义保持不变。
- Developer：五类分类方格；窄屏与大字体自动改为单列。分类页只显示元数据条目，揭示与复制仍走原有认证 gate。
- 设置：数据归属说明、备份传输入口、关于入口和设备保护说明，避免重复展示版本与大段标题。
- 24 dp 内容卡 / 18 dp 行卡 / 32 dp 主面板，全由 `CardTokens` 派生；平面填色取代每行描边，细分隔线保留于长分组。
- 认证器 / Developer / 设置的主 banner 共用紧凑品牌卡：88 dp 起、水平 24 dp / 垂直 12 dp 内边距；按字体放大统一增加高度并允许内容撑开。品牌名前景靠起始端，Logo 作为逻辑尾端放大裁切的静态淡底纹（200 dp；浅色 6.5%、深色 18%），不占独立图标槽位、不参与读屏或点击。仅认证器显示账户总数，置顶筛选不改变该总数；开发者与设置不显示概览统计或口号。
- 浮动导航栏保留三个永久文字标签；2026-09-25 改为随主题变化的半透明浅色 / 深色胶囊，使用细边框、柔和阴影和浅色选中底，最小触摸区域仍为 48 dp。
- Banner 的文字与账户数首帧即以完整对比度显示；只对装饰底纹做 180 ms 单次淡入，不再让整个卡片变透明。首次开启页直接呈现内容，移除原有 440 ms 整页淡入。无无限动画、认证延迟或持久化动效状态，遵循系统动画时长缩放。
- 钥匙主资产为 `design/brand/shiyifang-logo.svg`，统一生成彩色 / 单色 Android VectorDrawable 及启动图标。保留窄柄原长度和蓝金深度，SVG 没有嵌入位图。首页 Banner 与首次开启页的中文品牌名使用已选「轻行书」透明 PNG，由 `RescueAuthWordmark` 统一绘制；浅色墨蓝、深色主题前景色，随字体设置缩放，读屏保留产品名。英文继续使用原生文字。
- 所选运行时品牌资源随源码提交；候选图与临时预览不纳入版本库。没有网络图片、字体下载或新的运行时依赖。截图由 instrumented 测试注入虚构元数据与明确标注的占位 / 示例码生成，不含真实秘密，输出仅用于本地验证。
- 英文 / 简体中文与深色主题同时验证；界面不能依赖固定屏幕高度，长内容必须可滚动。

### 交互验收补充（2026-09-14）

- 账号或服务已被删除 / 重命名时，保留详情页返回入口并展示不可用状态；Undo 恢复同一账号后可以继续显示详情。
- Developer 表单保存期间禁用保存和返回操作；完成或失败后恢复可操作状态。
- 恢复码搜索结果进入所属账号的恢复码页，TOTP 搜索结果进入所属账号详情；路径参数经过 URI 编码。

### 服务账户列表与账户详情（2026-09-28）

- 服务下的账户排列为连续卡片组，名称与简短的验证码 / 恢复码组数对齐；头像使用低对比度单色首字母，置顶状态仍可见。每行继续由 LazyColumn 独立组合，长列表不一次性构建全部账户；分组圆角、分隔线与内边距由 CardTokens 提供。添加账户由悬浮「＋」的上下文面板进入，列表底部不重复放置添加行。
- 账户详情仅在页头显示账户名，移除重复 Provider 名称、图标和统计卡；置顶、重命名、移动、合并和删除放入页头原生菜单。悬浮「＋」提供当前账户的验证码 / 恢复码添加入口，复用全局按钮组件、位置状态和动画 token。
- 验证码按两组显示，复制仍传递最新、未插入分隔空格的原始值和原有 credential / stable / account ID。暂无有效码时禁用复制，保留删除入口。固定长度的数字展示在窄屏或大字体下按可用宽度收敛，其他文字继续正常缩放。
- 验证码正常状态直接明文显示，不新增显隐开关或再次揭示步骤。版面审阅使用固定虚构示例码 `123456` / `12345678`，不从用户截图或实际 Vault 采集验证码。
- 验证码卡使用小圆环表达剩余时间，秒数有完整读屏含义，临近过期使用语义 error 色；仅随已有状态更新，不新增计时器或连续动画。复制使用轻量主题按钮，算法和位数降为辅助信息。
- 恢复码入口明确区分组数与可用总数，不展示任何恢复码值；点击仍打开当前账户的恢复码页。

### 视觉减字（2026-09-25）

- 延续 Studio 配色、品牌图形、卡片层级和统一 banner 尺寸；移除页面上重复的口号和解释性副标题。
- 概览用大数字与短标签，列表用图标计数，分类用数字徽标；完整计数含义通过本地化 accessibility 描述保留。
- 添加、复制等通用操作用 48 dp 图标按钮，并提供本地化读屏标签和长按提示。导航、分类、导入类型保留可见短标签。
- 设备归属、加密与认证说明用图标和短标签表达；传输中心保留“手动导出 / 独立 PIN / 合并导入”三项明确说明和文件格式。
- 不删去错误原因、认证要求、破坏性确认、PIN 要求或导入冲突信息。图形替换不改变回调、认证 gate、数据或导入语义。
- 新截图继续只注入虚构元数据和空验证码；验证中英文、深色和大字体下的可达性。

### Dock 与外观模式（2026-09-25）

- Dock 使用统一 token 的半透明 surface、边框、圆角与阴影；选中态使用主题色，深色模式不保留固定的浅色底或墨色文字。
- 设置新增外观入口，提供“跟随系统 / 浅色 / 深色”；默认跟随系统。图标配短标签，不增加解释段落。
- 外观模式作为非敏感 UI 偏好保存在已有 DataStore 中，独立于 Vault 数据库；旧版没有该字段时按跟随系统处理。
- 手动切换外观通过 Compose 状态更新，不主动重建 Activity、不销毁 App Shell / Authenticator ViewModel，也不改变认证或会话语义。系统栏图标同步明暗。
- Dock 默认主体高度为 56 dp（48 dp 触摸区域 + 上下各 4 dp 内边距），大字体按内容增高；三个导航标签保持可见。
- 选中底块用 220 ms 缓入缓出滑移，图标轻微放大并过渡文字 / 图标颜色。导航回调立即执行，快速连续点击从当前动画位置转向新目标；RTL 镜像位置，系统关闭动画时直接到位。不增加 Dock 或动画独立设置。
- 2026-09-26：Dock 关闭默认 Material 点击波纹 / 按压加深，以滑动底块作为唯一选中背景；保留独立的键盘焦点描边和原有 Tab 语义。其它控件的点击反馈不受影响。

### 页面转场（2026-09-27）

- `RescueAuthNavigationMotion` 明确配置四个进出场回调，取代 Navigation Compose 2.8.2 默认的 700 ms 整页淡入淡出。
- 三个首页由同一个 `HorizontalPager` 承载，按 Dock 顺序左右推移；Dock 留在原位，指示块直接读取 `currentPage + currentPageOffsetFraction`，与页面共用移动进度。统一 220 ms、`FastOutSlowInEasing`，跨两个标签也经过对应的中间位置；不运行第二套指示块位移动画。
- 导航继续由按钮驱动，不额外增加横滑切页手势。连续点击先取消上一次页面滚动，再从当前位置移向新目标；系统返回从开发者 / 设置回到账户，详情返回保留此前选中的首页。
- 保留原 `authenticator` 起始路由 ID 和 `developer` / `settings` 旧入口，旧返回栈可解析后归入首页容器；保存 / 恢复详情页时保留原先首页选择。
- 详情向逻辑末端进入：前景页移动一个屏宽，背景页仅移动屏宽的 18%，220 ms；返回反向揭开前页，200 ms。页面保持不透明，不缩放或拉伸文字。RTL 镜像方向，系统关闭动画时直接到位。
- NavHost 保持全高，只有三个首页消费 Dock 的底部留白；离开首页时保留该留白，避免 Dock 隐藏 / 出现导致转场中的页面突然变高或变矮。
- 原生中间帧检查覆盖方向、返回、稳定尺寸、Dock 位置、快速连续点击、RTL、关闭动画和 Banner 首帧文字对比度；截图属于忽略的构建输出。

### 全局添加入口（2026-09-27）

- 账户与开发者首页共用 App Shell 持有的「＋」，位于页面滑动容器之外；默认在逻辑末端、Dock 上方。切换这两个首页不重建按钮、不随页面平移。
- 按钮支持拖动，松手吸附最近的左右边缘；活动范围避开系统栏、标题区和 Dock。用归一化坐标保存位置，切页、进出设置及 Activity 状态恢复后保留，窗口尺寸变化后仍在边界内。它只悬浮在应用内，不请求系统悬浮窗权限。
- 设置页让按钮在 180 ms 内缩小消失；回到账户或开发者时弹簧放大并轻微左右摆动后停止。动画可中断，系统关闭动画时直接到位。切页中与消失中的按钮不接受点击或拖动。
- 点击账户页「＋」打开卡片式底部选择面板，区分添加验证码与新建服务；开发者页打开同一面板模板的五类条目选项。根据内容与窗口高度自适应，长内容、大字体可滚动；不再使用首页添加下拉菜单。选项同步关闭选择面板并交给原有表单 / 导航流程，不延迟保留待执行动作。
- 列表底部保留 `AddActionTokens.contentClearance`（按钮高度 + 上下安全间距），最后一项可以完整滚到默认按钮位置上方；Snackbar 同样避让默认位置。留白属于滚动内容，不改变页面视口高度。拖动后临时覆盖的内容可以再次移动按钮避开。
- 首页入口仍由 App Shell 的固定悬浮层绘制；支持新增的二级 / 更深列表页复用同一个按钮组件和位置状态。编辑、搜索、设置和传输工作流不增加全局「＋」，表单中的添加字段 / 变量仍为局部操作。多按钮展开的 Speed Dial 暂不实现。

### 二级及更深页面添加入口（2026-09-28）

- 服务账户列表：「＋」提供添加账户、添加验证码、添加恢复码。验证码 / 恢复码归属于账户；只有一个账户时直接使用该账户，多账户时先在当前服务内选择。选择面板也提供“添加账户”；创建成功后使用实际返回的账户继续原验证码 / 恢复码流程，不必退出重选。取消或创建失败时不继续。新增账户继续调用现有管理表单和持久化路径。
- 账户详情：「＋」仅提供添加验证码和添加恢复码，自动携带当前账户；验证码表单预填当前服务和账户，新建请求清理上次关闭后遗留的表单草稿。
- 恢复码列表：「＋」直接打开新增恢复码表单，不再经过类型选择。来自上级页面的新增入口在所属账户加载成功后仅自动打开一次；关闭后或恢复页面状态时不重复弹出。账户不可用时不提供添加入口。
- 开发者分类：「＋」直接进入该分类的现有新建表单，不再重复选择五类条目。开发者首页仍保留分类选择；已有条目的编辑 / 显示 / 复制认证边界不变。
- 服务或账户被删除后关闭失效的选择面板；账户选择始终限定在当前服务。扫描界面隐藏添加入口，列表尾部和 Snackbar 使用已有按钮避让 token。
- 不修改悬浮按钮外形、拖动吸边、缩放摆动、保存位置的实现；服务、账户、恢复码和开发者分类共用 Shell 的 `FloatingAddPosition`。

### 详情安全提示与统一操作栏（2026-09-26）

- 五类 Developer 详情的安全提示采用已选定的卡片顶栏方案：`ProtectedFieldsCard` 将“显示或复制需验证”放入字段卡片；点击顶栏打开完整说明。说明弹层不读取秘密、不触发或授予认证，切换条目后关闭；显示 / 复制继续直接走原有 one-shot re-auth 回调。
- Developer 详情与五类添加 / 编辑表单共用 `RescueAuthActionBar`。详情为起始端“删除”、末端“编辑”；表单为起始端“取消 / 返回”、末端“继续 / 保存”。普通删除 Undo、签名密钥删除确认和两步表单流程保持各自既有语义。
- 采用合并式容器：细边框、蓝灰色主操作底色、图标配文字，无阴影、无渐变；删除使用主题 error 色。外形、颜色和间距集中在 `CardTokens`，主操作默认分配较多宽度，窄屏或大字体改为均分；窄屏且大字体时图标置于文字上方，允许整组等高增高。
- 操作栏位于页面底部，正文滚动时保持可达；共用导航栏与键盘 inset 处理。按钮最小高度 52 dp；保存期间沿用原有禁用条件，加载 / 条目不存在时不显示详情操作栏。
- 双按钮可用宽度固定为次操作 : 主操作 = 2 : 3（不含容器内边距与按钮间隙）；窄屏、大字体、禁用状态保持同一比例，文案允许换行，必要时图标与文案上下排列，两侧等高。
- 这套样式用于页面级操作组；验证码、秘密字段内的显示 / 复制等局部操作仍留在对应内容卡片中。
- 完整编辑器在读取 / 预填既有值前执行独立 fresh re-auth；直接进入或恢复编辑路由也会验证，失败返回详情。该要求由编辑入口逻辑实现，不给页面新增“编辑需验证”的说明文案。

### 统一输入框（2026-09-27）

- 搜索与表单统一使用 `RescueAuthTextField`：保留浅色白底 / 深色 surface、大圆角及现有描边，标签恢复 Material 浮动方式。空白且未聚焦时标签位于框内，聚焦或已有内容时缩小到上边框；标签预留空间随字体缩放，切换状态不移动输入槽。错误用语义 error 色，禁用状态降低对比度。颜色和尺寸来自 `CardTokens`，圆角复用 `rowShape`。
- 单行输入槽至少 56 dp；多行字段随内容增高。浅色与深色均随主题解析，不引入独立输入框外观设置。
- 编辑、选择、输入法动作和密码变换由 Compose `BasicTextField` 保留，槽内图标 / 占位 / 边框使用 Material 装饰层；只读下拉、显隐按钮和校验继续由原有调用方处理。组件不缓存或持久化输入值，错误状态保留读屏语义。
- 覆盖验证码、恢复码、服务/账户管理、开发者五类凭据、备份 PIN、旧版密码与搜索；原有字段 tag、回调、校验、认证与保存边界保留。
- 密码类输入的显隐操作放在输入槽尾部，使用眼睛 / 划线眼睛图标和对应读屏提示，不再另放“显示 / 隐藏”文字按钮。旧版导入密码、原生导入 PIN、导出 PIN 与确认 PIN、手动 TOTP 密钥默认遮罩；每个输入框独立控制，显隐状态仅保存在当前表单内。开发者表单继续使用已有的框内眼睛按钮。

- 通用机密与环境变量按名称 / 内容成组，组间用轻分隔线区分。删除使用名称输入槽内的尾部图标，与内容的显隐按钮共享对齐方式，不能再把图标按“外置标签＋输入框”的总高度居中；两行输入槽保持等宽。添加字段 / 变量属于次级操作。
- 验证码填写态不重复方法选择说明和“手动”分区标题；更换方式收在弹层标题行，普通字段间距统一，底部取消 / 添加保持可达。
- 视觉对照使用相同的聚焦状态；默认态和键盘聚焦态分别展示。原生检查覆盖删除中心线、两行宽度和尾部图标列，并验证 1.5 倍字体。
- 名称与内容在同一组内使用等宽输入槽，组间以分隔线区分；不把删除放在外置标签和输入框旁边的居中行中。删除与显隐均使用槽内尾部按钮，删除用垃圾桶图形避免与“清空名称”混淆。

### 图文分组与按需说明（2026-09-28）

- 说明卡片、预览摘要与状态卡片通过 `RescueAuthIconHeader` 将图标放在标题左侧，标题和必要提示在同一文本列中换行。徽章 / 图形使用 `CardTokens.headerBadgeSize`（52 dp）与 `headerIconSize`（26 dp），图文间距使用 `headerGap`；长说明时图标对齐标题顶部，只有标题时垂直居中。

- 恢复码编辑表单移除重复介绍，直接展开到内容所需高度，长内容仍可滚动，保存操作保持可达。
